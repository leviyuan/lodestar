## 群内命令

直接发送下列词语，不加斜杠，大小写不敏感。这些命令控制当前群的 Agent 会话。

| 完整指令 | 缩写 / 别名 | 行为 |
| --- | --- | --- |
| `hi` | — | 打开控制台；会话未运行时先启动 |
| `model` | `md` | 按 Agent 分组选择账号，再选择模型与推理档位（effort）并保存 |
| `stop` | `st` | 打断当前回复并取消排队消息，保留进程 |
| `kill` | `kl` | 关闭当前 Agent 进程，保存可恢复的会话记录 |
| `restart` | `rs` | 进程存活时打断并恢复当前会话；已停止时列出同目录的历史会话，选择后创建独立分支 |
| `clear` | `cl` | 关闭当前进程并开始新会话；已停止时提示先启动 |
| `compact` | `cm` | 压缩当前会话的上下文 |
| `agents` | `agent` | 查看可调用的 Agent 身份及可用状态 |
| `codex-login [备注]` | — | 用设备码登录 Codex；省略备注为设备默认账号，带备注为独立保存的额外账号 |
| `codex-login-cancel [备注]` | — | 取消本人在本群发起的 Codex 登录；只有一个等待任务时可省略备注 |
| `codex-accounts [页码]` | — | 卡片列出账号额度、调度分数、顺序与当前/优先账号标记 |
| `hi 备注` | — | 指定本次启动的 Codex 账号；`hi default` 使用设备默认账号，运行中换号会重启并恢复原 thread |
| `codex-account [备注]` | — | 查看本群选号策略；带备注指定后续启动的账号，`default` 表示设备默认账号 |
| `codex-account-delete 备注` | — | 删除额外账号的本地记录与独立凭据，清除各群对它的指定 |
| `codex-auto` | — | 清除本群手动指定，恢复自动选择最高分账号 |
| `task` | — | 创建、查看或删除绑定的飞书任务清单 |

模型列表来自各账号的模型目录，获取失败显示 `MISS`。同账号切换 Claude 或 DSH 模型从后续回复生效，Codex 的持久模型设置需重启会话生效；跨账号或后端切换只允许在空闲时进行。账号接入、模型补录与额度说明见[账号与模型](models.md)。

## Codex 设备码登录与多账号

默认账号沿用设备上直接执行 `codex` 的登录态：使用 daemon 原始环境中的 `CODEX_HOME`，未设置时为 `~/.codex`。`codex-account` 只改变当前群后续 Codex 进程的认证选择，不覆盖默认账号，也不改变其他群。额外账号的备注名可包含中文和空格，不能包含换行或路径分隔符；`default`、`默认` 为保留名称。

额外账号不再使用时，发送 `codex-account-delete 工作`。删除会移除该账号的本地记录、独立认证目录和额度缓存，并清除所有群对它的指定，这些群下次启动恢复自动选号；共享会话历史、配置和其他账号保留。正在被会话、委派任务、额度或模型查询使用的账号不能删除；登录中的账号先用 `codex-login-cancel 工作` 取消。备注必填，设备默认账号不能通过此命令删除。需要重新添加时使用 `codex-login 工作`；本地删除不会注销 OpenAI 账号或取消订阅。

发送 `codex-login 工作` 后，Lodestar 会显示登录卡片，并在同一张卡里更新连接、授权、校验和结果。验证码与授权入口突出显示，结束后移除验证码。在手机或电脑浏览器中登录要保存的账号，输入验证码；授权结果会自动发回原群。凭据由 Codex 保存并刷新，不需要把密码或 Token 发给机器人。设备码登录须已在 ChatGPT 个人安全设置或工作区权限中启用；登录等待上限为 15 分钟，失败后重新发送命令。

新会话和委派任务启动时默认自动选号。Plus、Pro 5×、Pro 20× 的周额度分别按 1、5、20 份折算（原生套餐标识为 `plus`、`prolite`、`pro`），周分数为 **周剩余份额 ÷ 距周重置小时数**。Plus 的满 5h 窗口按 0.15 份计算，短窗分数为 **5h 剩余份额 ÷ 距5h重置小时数**，最终取周分数和短窗分数的较小值；Pro 使用周分数。所有模式都选择最高分，同分优先当前可连续使用额度更多的账号。两种窗口约束同一份消耗，不相加。

启动和换号优先使用 daemon 内上次成功的额度缓存，能选出账号就直接启动，不等待实时额度查询或其他账号补缓存。网络刷新失败会保留这份缓存；没有可用缓存时才重新查询。`hi`、`codex-accounts` 和回复 footer 仍展示实时查询结果，失败显示 `MISS`。重新登录会清空对应缓存；已由实际请求确认耗尽的账号，必须通过实时查询确认恢复，不能用旧缓存解除耗尽记录。

成功读取 Plus 额度但未返回 5h 窗口时，按满额 0.15 份、完整 5 小时计算短窗分数；界面显示满额，但不编造具体重置时刻。整个请求失败、已返回窗口缺百分比或缺重置时间仍显示 MISS。自动 Ultra 只用 Pro，且启动或换号时周余量至少 0.5 份（Pro 5× 剩 10%，Pro 20× 剩 2.5%）；运行中跌破该门槛不立即切号。没有合格 Pro 时等待周额度恢复，不自动用 Plus。其他实际限额、登录状态、目标模型与 effort、账号身份和查询错误仍参与自动选择。

手动指定最高优先级：`hi 工作` 直接使用该账号启动，不读额度、不限制 Plus/Ultra、不检查 0.5 份门槛，也不因本地目录失败或未收录模型而阻挡，真实登录及请求错误由 Codex 返回。只覆盖本次启动，不改变原有群偏好；同一账号正在运行时展示状态，换号会重启并恢复原 thread。`hi default` 指定设备原生账号。需要持久指定时仍可用 `codex-account 工作` 后 `restart`，`codex-auto` 清除该设置。运行过程中确认耗尽后按自动规则换号续跑。临时会话继承持久策略，委派任务按自己的 effort 自动选号。重新登录仍与实际占用账号的原生进程互斥，添加其他备注账号可独立进行。

原生主 turn 确认额度耗尽后，Lodestar 自动确认会话落盘、停止旧 Codex 进程，用下一账号恢复同一 thread 并继续任务；已接受的原始输入不重放，明确拒绝的输入才重新提交。连续耗尽会继续换号，所有可用账号耗尽则等待接口确认恢复，`stop` 可取消。网络、认证、普通 HTTP 429 和模型满载不触发换号；模型满载保留原来的同模型重试。额度耗尽记录保存在私有 `codex-quota-blocks.json`，防止重启后使用尚未恢复的账号。退出或落盘确认失败会显示错误，并阻止新进程接管。

Linux/macOS 下，额外账号通过软链接共用默认账号的配置、会话、Skills、插件文件和会话写锁，SQLite 状态使用共享目录；认证文件、模型缓存和临时运行文件保持独立。Windows 创建文件软链接需要系统允许；失败直接报告，不自动改用复制。账号备注与群选择位于 Lodestar 数据目录的 `codex-accounts.json`，额外认证位于 `codex-accounts/<内部 ID>/auth.json`。这些文件不应进入项目仓库。

账号命令统一回复简洁卡片：长错误可展开查看；`codex-accounts` 仅展示主额度，进度条为六格，每页显示 4 个记录，同时标出当前模式下的顺序和 `份/h` 分数，后续页用 `codex-accounts 2` 等命令查看。每页底部列出全部 Codex 账号命令，包括登录、取消登录、查看、指定、自动选择、删除及 `hi` 用法。列表按账号身份去重，未知身份或查询失败显示 `MISS`。

`hi` 的额度区使用同款六格彩色进度条和重置倒计时，各窗口纵向排列，重置卡次数独占一行。活跃项目中的 Codex 会话在行尾标注进程实际使用的账号备注，账号尚未确定时省略该备注，自动换号后再次查看会显示新账号；待下次启动生效的指定不会提前改变该标注。`hi` 与回复 footer 只显示实际使用账号的额度；footer 保留 `4.1h·7%·[6.9d·17%]` 紧凑格式，自动换号后跟随新账号。重置卡次数只出现在账号明细和 `hi` 中。

## 独立工作区

需要独立修改文件时，在项目主群使用 worktree：

| 完整指令 | 缩写 / 别名 | 行为 |
| --- | --- | --- |
| `worktree` | `wt` | 列出项目的 `work/*` 分支和工作区状态 |
| `worktree feature-x` | `wt feature-x` | 创建或加入 `<project>[feature-x]` 群和同级 worktree 目录，使用 `work/feature-x` 分支 |

已合并且未挂载的分支会折叠隐藏，再次启用时更新到主线。卡片上的“删”会检查对应群没有运行中的会话、工作区没有未提交变更，再解散群并删除 worktree；Git 分支保留。

## 临时会话与对话分支

临时会话共享当前工作目录，适合在同一项目里另开一段对话：

| 完整指令 | 缩写 / 别名 | 行为 |
| --- | --- | --- |
| `btw` | — | 创建 `<session>*MMDD-HHMM` 临时群，继承账号、模型和工作目录，启动新会话 |
| `fork` | `fk` | 选择一条用户输入，在临时群里从这条输入之前分叉 |
| `back` | `bk` | 选择一条用户输入，让本群接到这条输入之前的新分支 |
| `bye` | — | 停止并解散当前临时群，仅适用于 Lodestar 创建的临时群 |

`fk`、`bk` 和从历史记录恢复的 `rs` 都使用后端原生 fork，保留源对话。选第 N 条输入表示回到它发出之前，选中的输入不包含在新分支内。Claude 的新分支在首条输入时获得会话 id，准备状态会持久保存。

**分叉和回退只改变对话历史，不回滚文件或撤销 Shell、MCP 等外部操作。** `bk` 会附上已观察到的文件变更记录；需要目录隔离时使用 `wt`。

## 多模型任务

主 Agent 可以通过 `lodestar-agent` 查询实时身份，再把任务交给一个或多个模型。同一个任务选择多个身份时并发执行；后续追问可继续使用各模型的原生会话。

被调用的 Agent 可以编辑文件、执行命令、使用 MCP 和 Skill；委派只允许一层，被调用的 Agent 不能继续派工。它们与主 Agent 共享工作区，修改会立即可见。运行状态和结果通过卡片展示；需要用户输入时暂停，由主 Agent 回填答案后继续。委派产生的会话不会混入主群的 `rs` 历史列表。

首轮完成后，返回内容包含原生会话 ID（文本中的 `Session:`；JSON 中的 `workers[].session_id`）和本轮结果（`workers[].output`）。后续只需传入这个 ID 和新的一句输入：

```bash
# desc: 首轮调用并返回 JSON 结果
lodestar-agent run --identity '<identity-id>' --prompt '完成第一步' --json
```

```bash
# desc: 沿用历史会话继续第二轮
lodestar-agent run --session '<session-id>' --prompt '根据上面的结果继续第二步' --json
```

第二轮及后续轮次恢复同一个后端原生会话，自动沿用原身份和上一轮的 effort，每轮产生新的 `run_id`。`--identity` 可省略，指定时必须与原身份一致；可用 `--effort` 显式选择本轮档位。多模型首轮会分别返回各 worker 的会话 ID，续跑时一次选择一个会话。也可继续使用 `lodestar-agent follow-up '<run-id>' --prompt '下一步'`；原 run 包含多个 Agent 时需用 `--identity` 指定。

续跑要求原任务已经结束，且属于同一个 Lodestar 群会话和工作目录。持久化的委派历史仍可用时，daemon 重启后也可凭原会话 ID 继续；会话不存在、身份不可用或原生恢复失败会报错。同一个原生会话不能同时执行两轮。`run`、`follow-up`、`status` 支持 `--json`；使用 `--stdin` 可输入多行任务，`--no-wait` 立即返回启动状态，随后通过 `status <run-id>` 查询结果。

`lodestar-agent` 只能在 Lodestar 管理的 Agent 进程里调用。命令用法见 [Agent Skill](../src/agent-skill.ts)。

## 飞书任务清单

发 `task`，点“启用”可创建并绑定 `<project>[lodestar]` 任务清单。删除需要在卡片上再次确认，会删除整个清单及其中任务。该面板管理清单绑定，任务执行由用户和 Agent 安排。

## 本机通知

脚本可通过 HTTP 向项目群发送通知，支持 `info`、`warn`、`error`，以及本地图片、交互按钮或文字回复：

```bash
curl -sS -X POST http://127.0.0.1:9876/notify \
  -H 'Content-Type: application/json' \
  -d '{"project":"ops","level":"error","text":"构建失败，截图如下","images":["/abs/shot.png"]}'
```

按钮点击结果可以 POST 到指定的本机 `callback`，或通过 `GET /notify/result/<notify_id>` 查询。需要文字回复时设置 `allow_reply: true`，卡片会提供“回复”按钮；文字回复模式与自定义按钮模式不能同时启用。字段和协议见 [feishu-notify Skill](../src/notify-skill.ts)。daemon 启动时会将该 Skill 同步到 Codex 和 Claude 的 Skill 目录。

## 文件与生图

单个出站文件不能超过 **30 MB**（30 × 1024 × 1024 字节）。Agent 在交付前检查大小，超限先压缩或分卷；发送层也会拒绝超限文件。

Codex 生图完成后，提示词和图片放在同一个折叠面板中，点击展开查看图片并放大预览。无法嵌入时，图片仍会单独发送。
