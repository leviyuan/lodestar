# 群内使用指南

## 群内命令

直接发送下列词语，不加斜杠，大小写不敏感。这些命令控制当前群的 Agent 会话。

| 完整指令 | 缩写 / 别名 | 行为 |
| --- | --- | --- |
| `hi` | — | 打开控制台；会话未运行时先启动 |
| `model` | `md` | 按 Agent 分组选择账号，再选择模型与推理档位（effort）并保存 |
| `stop` | `st` | 打断当前回复并取消排队消息，保留进程 |
| `kill` | `kl` | 关闭当前 Agent 进程，保存可恢复的会话记录 |
| `restart` | `rs` | 进程存活时打断并恢复当前会话；已停止时列出同目录的历史会话，选择后创建独立分支 |
| `clear` | `cl` | 关闭当前进程并开始新会话；已停止时提示先启动 |
| `compact` | `cm` | 压缩当前会话的上下文 |
| `agents` | `agent` | 查看可调用的 Agent 身份及可用状态 |
| `claude-sub` | — | 查看 Claude Code 订阅在 Lodestar 中的开关和可用状态 |
| `claude-sub on` | — | 启用 Claude Code 订阅来源，所有群共用 |
| `claude-sub off` | — | 禁用 Claude Code 订阅来源，保留本机登录态，所有群共用 |
| `codex-login [备注]` | — | 用设备码登录 Codex；先不带备注登录默认账号，再带备注添加额外账号 |
| `codex-login-cancel [备注]` | — | 取消本人在本群发起的 Codex 登录；只有一个等待任务时可省略备注 |
| `codex-accounts [页码]` | — | 卡片列出账号额度、调度分数、顺序与当前/优先账号标记 |
| `codex-reset [备注]` | — | 直接使用一次 Codex 重置卡；省略备注为当前运行账号，`default` 指定设备默认账号 |
| `hi 备注` | — | 指定本次启动的 Codex 账号；`hi default` 使用设备默认账号，运行中换号会重启并恢复原 thread |
| `codex-account [备注]` | — | 查看本群选号策略；带备注指定后续启动的账号，`default` 表示设备默认账号 |
| `codex-account-delete 备注` | — | 删除额外账号的本地记录与独立凭据，清除各群对它的指定 |
| `codex-auto` | — | 清除本群手动指定，恢复按优先级与额度评分自动选号 |
| `task` | — | 创建、查看或删除绑定的飞书任务清单 |
| `files` | — | 查看当前工作目录的交付模式及本群文件夹入口 |
| `files on` | — | 开启当前工作目录的云空间交付，创建或复用本群文件夹 |
| `files off` | — | 当前工作目录恢复聊天附件，保留云空间文件和群目录绑定 |

模型列表来自各账号的模型目录，获取失败显示 `MISS`。同账号切换 Claude 或 DSH 模型从后续回复生效，Codex 的持久模型设置需重启会话生效；跨账号或后端切换只允许在空闲时进行。账号接入、模型补录与额度说明见[账号与模型](models.md)。

Codex 和 Claude 执行任务时，可以直接发消息补充要求或纠正方向，无需等待整轮回复结束。消息会交给正在运行的任务，在后端下一次可接收输入时生效；Agent 实际收入补充消息后，按原生执行记录中的连续输入区段切换到新卡，顶部「📥 追加」列出整批补充内容。中间没有 Agent 思考、回复或工具执行的连续补充会合并在一张卡里。在此之前的输出仍留在旧卡，之后的输出进入新卡，运行中的工具随卡接续；新卡发送成功时一并撤销本批消息的等待表情，旧卡标记已续至下一张，任务继续执行。Claude 的兼容来源（GLM、DeepSeek、OpenRouter 等）沿用这一行为。消息恰好赶上回合结束时会接着处理；进程仍在启动或恢复时暂存，提交失败会明确提示。`stop` 同时取消尚未处理的追加消息。DeepSeek Harness 仍按下一轮批次处理执行中收到的消息。

## Codex 设备码登录与多账号

默认账号沿用设备上直接执行 `codex` 的登录态：使用 daemon 原始环境中的 `CODEX_HOME`，未设置时为 `~/.codex`。`codex-account` 只改变当前群后续 Codex 进程的认证选择，不覆盖默认账号，也不改变其他群。额外账号的备注名可包含中文和空格，不能包含换行或路径分隔符；`default`、`默认` 为保留名称。

发送 `codex-reset` 直接为当前运行的 Codex 账号使用一次重置卡；`codex-reset 工作` 为指定账号使用，`codex-reset default` 为设备默认账号使用。当前没有运行的 Codex 账号或正在等待选号时，必须带备注。命令不会切换账号或重启会话，额度不足时也不会自动使用重置卡。回执区分已重置、本次请求此前已完成、没有可重置窗口、没有可用卡，并重新读取剩余卡数和额度；查询失败显示 `MISS`，已确认的扣卡结果仍保留。同一消息的网络重试复用幂等标识，重新发送命令则是新的一次使用请求。接口失败或结果未知时，先用 `hi` 核对卡数、`codex-accounts` 核对额度。

额外账号不再使用时，发送 `codex-account-delete 工作`。删除会移除该账号的本地记录、独立认证目录和额度缓存，并清除所有群对它的指定，这些群下次启动恢复自动选号；共享会话历史、配置和其他账号保留。正在被会话、委派任务、额度或模型查询使用的账号不能删除；登录中的账号先用 `codex-login-cancel 工作` 取消。备注必填，设备默认账号不能通过此命令删除。需要重新添加时使用 `codex-login 工作`；本地删除不会注销 OpenAI 账号或取消订阅。

添加额外账号前，先发送不带备注的 `codex-login` 完成默认账号登录。默认账号未登录 ChatGPT 或仍在授权时，`codex-login 工作` 会直接提示先完成默认账号登录，不创建额外账号记录或生成设备码；默认账号状态查询失败会显示具体错误。已在设备原生 Codex 中登录的默认账号也可使用，包括系统钥匙串保存的登录态。

默认账号检查通过后，`codex-login 工作` 会显示登录卡片，并在同一张卡里更新连接、授权、校验和结果。验证码与授权入口突出显示，结束后移除验证码。在手机或电脑浏览器中登录要保存的账号，输入验证码；授权结果会自动发回原群。凭据由 Codex 保存并刷新，不需要把密码或 Token 发给机器人。设备码登录须已在 ChatGPT 个人安全设置或工作区权限中启用；登录等待上限为 15 分钟，失败后重新发送命令。

新会话和委派任务启动时默认自动选号。优先距离周重置不超过 5 小时的账号，越早重置越优先；其余账号按评分选择。周额度刚恢复的账号不再抢先承接一次前台任务。所有账号仍须通过模型、套餐和实际额度检查。任一订阅窗口用完后，有可用消费积分的账号仍参与调度；仅剩积分的账号排在有订阅额度的账号之后，积分更多的优先，同额保持稳定顺序，周临期优先不适用于这类账号。

后台发现主额度是完整未使用的周窗口后，每个真实账号独立随机等待 30–60 分钟，到点直接向上游重新查询，绕过一分钟缓存；只有原始已用严格为 0、周窗口 10080 分钟、读取时重置时间仍恰好相差 7 天，且已返回的短窗口同样未使用，才发送一句简短问候。其他设备已使用、身份改变或查询失败时不发送；显示取整后的 `0%` / `7.0d` 不构成依据。账号别名在本机合并去重；不同设备之间没有原子锁，查询与发送间仍存在极短的竞态。

激活使用当前成本最低的 `gpt-6-luna`、原生目录提供的最低推理档位和标准速度，发送前校验属于主额度；模型缺失或被分配到独立计量桶时不换用其他模型。请求只包含问候，不创建 Codex thread，不加载会话历史、项目指令、Skill 或工具，不在群聊输出问候。只有成功终态及真实 token 用量才记为成功，随后重新读取上游重置时间，不在本地推算。失败诊断写入日志和 `codex-accounts`，下一次检查重新随机等待 30–60 分钟；已确认用量后的刷新失败不会重发。当前零上下文通道需要 Codex 原生文件登录态，令牌刷新仍由原生接口完成；钥匙串等无法通过原生接口导出令牌的存储会显示后台激活 MISS，不改变认证存储，普通会话仍可使用。

其余账号按分数从高到低选择，同分优先当前可连续使用额度更多的账号。Plus、Pro 5×、Pro 20× 的周额度分别按 1、5、20 份折算（原生套餐标识为 `plus`、`prolite`、`pro`），周分数为 **周剩余份额 ÷（距周重置小时数 − 5）**，提前 5 小时安排消耗；临期账号直接按优先级处理，不做零或负分母计算。Plus 的满 5h 窗口按 0.15 份计算，短窗分数仍为 **5h 剩余份额 ÷ 距5h重置小时数**，普通评分取周分数和短窗分数的较小值；Pro 使用周分数。两种窗口约束同一份消耗，不相加。

启动和换号优先使用最近一次成功的额度缓存，能选出账号就直接启动，不等待额外查询。所有来源、群和 Agent 的额度查询共用一分钟惰性缓存，并合并同账号并发请求；过期后按需查询，失败冷却依次为 1、2、4、5 分钟，并遵守上游更长的等待时间。这不是每分钟自动刷新全部账号。`hi`、`codex-accounts` 也遵守缓存与冷却，网络或限流导致刷新失败时，额度区域保留同账号的成功缓存，账号列表仍展示本次调度失败原因。回复底部刷新失败或进程已退出时，按原格式显示本条回复所属账号的成功缓存，没有缓存仍显示 `MISS`。重新登录、删除账号及额度重置会清空对应缓存，认证失败也不会继续显示旧额度；已由实际请求确认耗尽的账号，必须通过实时查询确认恢复，不能用旧缓存解除耗尽记录。

自动选号成功后，其他账号的缓存过期、模型档位不支持或查询失败不会单独发送警告卡或消息；具体原因保留在日志中，也可用 `codex-accounts` 主动查看。此规则同时适用于首次启动、恢复会话和自动换号。无法选出账号、任务必须等待额度恢复或当前账号实际执行失败时，仍会明确提示。

成功读取 Plus 额度但未返回 5h 窗口时，按满额 0.15 份、完整 5 小时计算短窗分数；界面显示满额，但不编造具体重置时刻。整个请求失败、已返回窗口缺百分比或缺重置时间仍显示 MISS。自动 Ultra 只用 Pro；启动或换号时，有可用消费积分即可通过周余量门槛，没有积分则仍要求周余量至少 0.5 份（Pro 5× 剩 10%，Pro 20× 剩 2.5%）。周余量不足且积分未知时显示 MISS。运行中跌破该门槛不立即切号。没有合格 Pro 时等待额度恢复或积分补充，不自动用 Plus。其他实际限额、登录状态、目标模型与 effort、账号身份和查询错误仍参与自动选择。

手动指定最高优先级：`hi 工作` 直接使用该账号启动，不读额度、不限制 Plus/Ultra、不检查 0.5 份门槛，也不因本地目录失败或未收录模型而阻挡，真实登录及请求错误由 Codex 返回。只覆盖本次启动，不改变原有群偏好；同一账号正在运行时展示状态，换号会重启并恢复原 thread。`hi default` 指定设备原生账号。需要持久指定时仍可用 `codex-account 工作` 后 `restart`，`codex-auto` 清除该设置。运行过程中确认耗尽后按自动规则换号续跑。临时会话继承持久策略，委派任务按自己的 effort 自动选号。重新登录仍与实际占用账号的原生进程互斥，添加其他备注账号可独立进行。

订阅窗口达到 100% 且消费积分也确认耗尽，才判为额度用光；积分未知显示 MISS，上游明确禁止使用或达到消费限制仍会阻止调度。运行中的账号可在订阅额度用完后继续消费积分，不因百分比达到 100% 主动切号。原生主 turn 确认额度耗尽后，Lodestar 自动确认会话落盘、停止旧 Codex 进程，用下一账号恢复同一 thread 并继续任务；已接受的原始输入不重放，明确拒绝的输入才重新提交。连续耗尽会继续换号，所有可用账号耗尽则等待接口确认恢复，`stop` 可取消。网络、认证、普通 HTTP 429 和模型满载不触发换号；模型满载保留原来的同模型重试。额度耗尽记录保存在私有 `codex-quota-blocks.json`，防止重启后使用尚未恢复的账号。新的后台查询须确认订阅窗口恢复可用或积分增加才解除实际失败记录；旧正余额不能反复解封，确认积分耗尽后的补充可以恢复调度。退出或落盘确认失败会显示错误，并阻止新进程接管。

Linux/macOS 下，额外账号通过软链接共用默认账号的配置、会话、Skills、插件文件和会话写锁，SQLite 状态使用共享目录；认证文件、模型缓存和临时运行文件保持独立。Windows 创建文件软链接需要系统允许；失败直接报告，不自动改用复制。账号备注与群选择位于 Lodestar 数据目录的 `codex-accounts.json`，额外认证位于 `codex-accounts/<内部 ID>/auth.json`。这些文件不应进入项目仓库。

账号命令统一回复简洁卡片：长错误可展开查看；`codex-accounts` 按调度顺序排列，每页显示 4 个记录，标题为 `#1·备注「0.111/h」`；距离重置不超过 5 小时且有订阅额度的账号显示「临期优先」，仅剩积分的账号显示「积分」。正文依次显示“邮箱：…”、周额度和可选的 5h 额度，每个窗口一行，包含六格进度条、已用百分比和「5.2d」这样的真实重置倒计时；有消费积分时追加余额，未读到积分数据时显示 `积分 MISS`。后续页用 `codex-accounts 2` 等命令查看。每页底部的折叠面板列出全部 Codex 账号命令，包括登录、取消登录、查看、使用重置卡、指定、自动选择、删除及 `hi` 用法。列表按账号身份去重，未知身份或查询失败显示 `MISS`。

`hi` 的额度区紧凑展示全部账号，一账号一行；DeepSeek、GLM 的跨 Agent 入口不重复展示。Codex 使用账号备注，有消费积分时显示 `积分 62,500`，积分未知显示 MISS、确认没有则省略；重置卡另显示为“重置 N”，GLM 月工具只显示百分比，不显示次数与重置时间。活跃项目中的 Codex 会话在行尾标注进程实际使用的账号备注，账号尚未确定时省略该备注，自动换号后再次查看会显示新账号；待下次启动生效的指定不会提前改变该标注。`hi` 的各 Codex 账号与回复 footer 都只显示主额度自身的短时窗口和周窗口，不展示 Spark、gpt-reserve 等附加额度；footer 只显示当前实际使用账号，footer 保留 `4.1h·7%·[6.9d·17%]` 紧凑格式并在其后追加消费积分，自动换号后跟随新账号；已结束回复始终显示该回复所属账号的积分。重置卡次数出现在 `hi` 和 `codex-reset` 回执中。

## 独立工作区

需要独立修改文件时，在项目主群使用 worktree：

| 完整指令 | 缩写 / 别名 | 行为 |
| --- | --- | --- |
| `worktree` | `wt` | 列出项目的 `work/*` 分支和工作区状态 |
| `worktree feature-x` | `wt feature-x` | 创建或加入 `<project>[feature-x]` 群和同级 worktree 目录，使用 `work/feature-x` 分支 |

WT 使用独立工作目录，其文件交付、项目工具/MCP 配置与主目录分开。BTW/FK 始终共享来源目录的这些配置，包括从 WT 创建的临时群。任务清单属于项目级，主群、所有 WT 及其临时群共用。临时群的模型、账号在创建时继承，之后各自切换、互不影响。

已合并且未挂载的分支会折叠隐藏，再次启用时更新到主线。卡片上的“删”会检查对应群没有运行中的会话、工作区没有未提交变更，再解散群并删除 worktree；Git 分支保留。

## 临时会话与对话分支

临时会话共享当前工作目录，适合在同一项目里另开一段对话：

| 完整指令 | 缩写 / 别名 | 行为 |
| --- | --- | --- |
| `btw` | — | 创建 `<session>*MMDD-HHMM` 临时群，继承账号、模型并共享原工作目录配置，启动新会话 |
| `fork` | `fk` | 选择一条用户输入，在临时群里从这条输入之前分叉 |
| `back` | `bk` | 选择一条用户输入，让本群接到这条输入之前的新分支 |
| `bye` | — | 停止并解散当前临时群，仅适用于 Lodestar 创建的临时群 |

`fk`、`bk` 和从历史记录恢复的 `rs` 都使用后端原生 fork，保留源对话。选第 N 条输入表示回到它发出之前，选中的输入不包含在新分支内。Claude 的新分支在首条输入时获得会话 id，准备状态会持久保存。

**分叉和回退只改变对话历史，不回滚文件或撤销 Shell、MCP 等外部操作。** `bk` 会附上已观察到的文件变更记录；需要目录隔离时使用 `wt`。

## 多模型任务

主 Agent 按任务和可用能力自行选择原生 subagent 或 `lodestar-agent`，调用自身模型或 Agent 时也适用。使用 `lodestar-agent` 时先查询实时身份，再把任务交给一个或多个模型。同一个任务选择多个身份时并发执行；后续追问可继续使用各模型的原生会话。

被调用的 Agent 可以编辑文件、执行命令、使用 MCP 和 Skill，也可以通过 Lodestar 或原生子 Agent 继续派工，Lodestar 不设置委派层数上限。它们与主 Agent 共享工作区，修改会立即可见。会话委派需要输入时暂停，由调用方回填答案后继续；项目调用及其后续委派保持非交互执行。委派产生的会话不会混入主群的 `rs` 历史列表。

首层任务默认使用主 Agent 的工作目录，后续委派默认使用调用方的执行目录，不受调用命令时 Shell 当前目录影响。可用 `--workdir <路径>` 指定其中已存在的子目录：相对路径以主 Agent 的工作目录为基准，也支持范围内的绝对路径。路径会解析软链接，越界、目录不存在或指向普通文件都会报错。同一个 run 的多个 Agent 使用同一目录；需要不同目录时分别发起任务。

```bash
# desc: 在项目子目录中委派任务
lodestar-agent run --identity '<identity-id>' --description '检查应用代码' --workdir 'packages/app' --prompt '检查当前应用的代码并报告结果' --json
```

每次 `run` 和 `follow-up` 必须填写 `--description`（不超过 60 字的单行说明）。委派任务、原生子 Agent 和后台任务统一收在委派卡里，每项只显示状态和一句说明，展开可看任务类型、正文、结果、错误和最近三步动作。子 Agent 启动即展示，普通前台命令不会额外生成任务项；任务结束后显示实际耗时。

委派卡仍在群对话尾部时，新任务继续追加；容量满或群里出现新消息（包括主 Agent 新开的会话卡）后，下一项另开卡。旧任务继续原地更新，后台任务不再随新消息迁移。共享卡等全部任务结束后才停止更新；后续结果撑满卡片时，对应条目移到新卡。多模型委派的完整结果仍保存在任务记录中。

首轮完成后，返回内容包含原生会话 ID（文本中的 `Session:`；JSON 中的 `workers[].session_id`）和本轮结果（`workers[].output`）。后续只需传入这个 ID 和新的一句输入：

```bash
# desc: 首轮调用并返回 JSON 结果
lodestar-agent run --identity '<identity-id>' --description '完成第一步' --prompt '完成第一步' --json
```

```bash
# desc: 沿用历史会话继续第二轮
lodestar-agent run --session '<session-id>' --description '继续第二步' --prompt '根据上面的结果继续第二步' --json
```

第二轮及后续轮次恢复同一个后端原生会话，每轮产生新的 `run_id`。已有 Lodestar 历史时，省略 `--identity` 会沿用最新记录的身份和 effort；也可显式选择原后端下的其他身份、模型来源及 `--effort`。切换身份且不指定 effort 时，使用新身份的默认档位。多模型首轮分别返回各 worker 的会话 ID，续跑时一次选择一个会话。也可使用 `lodestar-agent follow-up '<run-id>' --description '继续下一步' --prompt '下一步'`；原 run 包含多个 Agent 时需用 `--identity` 选择原 worker，若还需换模型，使用该 worker 的原生会话 ID 加新身份恢复。

`session_id` 是原生会话唯一且不变的 ID；`run_id` 只是一次调用记录，不是另一套会话 ID。会话归属项目和群，`run --session` 与 `follow-up` 只允许恢复同一项目、同一群的已登记会话，不要求与原调用使用相同的会话绑定或项目绑定。禁止跨项目、跨群；未知或归属不明的 ID 即使指定 `--identity` 也会报错。

```bash
# desc: 在当前会话中恢复同项目同群的原生会话
lodestar-agent run --session '<原生会话 ID>' --identity '<identity-id>' --workdir 'packages/app' --description '继续已有工作' --prompt '继续上一轮任务' --json
```

恢复时 `--workdir` 可选择本项目内的其他现有目录，省略则沿用历史执行目录；相对路径以当前项目目录解析。项目以规范工作目录识别，群以 `chat_id` 识别；子目录不改变所属项目。新调用依照调用场景绑定当前会话或项目，旧记录不迁移。同项目同群内切换绑定方式时，旧调用的取消不会连带停止新调用。原生会话 ID 和所属后端保持不变，模型、来源与 effort 可以在原后端支持范围内调整。

同一个后端原生会话在开卡和执行期间不能重叠恢复。多 Agent 任务中某个 worker 已结束并退出后，可以单独续跑它，无需等待其他 worker。`run`、`follow-up`、`status` 支持 `--json`；返回的 `work_dir` 是实际执行目录，`resumed_from_run_id` 仅记录可用的恢复来源，不建立跨绑定方式的取消关系。使用 `--stdin` 可输入多行任务，`--no-wait` 立即返回启动状态。HTTP API 的 `session_id`、`identity_ids` / `identity_id` 和 `work_dir` 遵循同一规则。

会话委派与项目调用均不设置本地并发或任务数量上限，OpenRouter 也没有单独的本地限制。任务正文和 Agent API 请求体也不设置本地长度或大小上限。任务开卡后直接启动，上游限流和进程启动失败会明确返回错误。

Agent 在执行任务中调用其他 Agent 或模型时，必须绑定当前会话，使用不带 `--project` 的命令；通过 Shell、Python 或脚本调用也适用。禁止清除会话环境或借用项目凭据转成项目调用。没有有效会话上下文必须报错。独立服务、定时任务及其他软件调用必须使用项目绑定。两种模式不能作为失败后的替代路径，详见 [Agent Skill](../src/agent-skill.ts)。

### 从终端或脚本调用项目 Agent

独立服务、定时任务或其他软件通过 `--project <项目名>` 直接调用本机 daemon，无需在对应群启动主 Agent；Agent 执行用户任务时不能使用此入口。项目必须已有明确的群绑定和现有目录；worktree 使用完整的 `项目名[分支名]`，BTW/FK 临时会话名不作为项目入口。

```bash
# desc: 查询项目可用身份并发起独立任务
lodestar-agent --project '<项目名>' identities --json
lodestar-agent --project '<项目名>' run --identity '<identity-id>' --description '检查项目' --prompt '检查代码并报告结果' --request-id '<本次业务调用唯一编号>' --no-wait
```

每次项目调用在绑定群新建独立的“项目任务”卡，后续进度和结果更新原卡。它不复用会话委派卡，不读取或修改主会话的模型、账号和上下文；停止、重启、切换主会话不影响项目任务。可点击任务卡的“停止本次任务”，或使用同一 `--project` 下的 `cancel <run-id>`。两类任务仍共享实际工作目录。

项目入口面向传统软件，执行约定是不给调用方提问、不等待回答。调用方给出目标后，Agent 自行查明上下文、作出任务范围内的实现决策、持续执行并验证，直至完整完成目标；不能以计划、部分工作、索取输入或要求调用方安排更多 Agent 作为完成结果。真实阻断或底层故障仍须如实报告，不能伪造完成。`answer` 用于会话归属的各层委派，不支持 `--project`。

外部调用中的 Codex 同步、异步提问工具均会禁用，GPT-6 代码模式仍可执行任务。工具约束按本次调用生成；主 Agent 委派保留提问能力。

`status`、`follow-up` 和 `run --session` 均支持 `--project`；最后一个仍表示继续任务自身的原生 Agent 会话。只能恢复当前项目、当前群中已登记的原生会话；本轮按项目绑定创建，旧记录不迁移。新建和续跑都按本轮绑定决定是否允许提问，项目调用不会继承旧会话的交互规则。没有 `--no-wait` 时客户端等到任务终态；等待期间 Ctrl+C 会取消任务，普通 HTTP 断开不会取消已接受的任务。

```bash
# desc: 查询项目任务状态和执行结果
lodestar-agent --project '<项目名>' status '<run-id>' --json
```

普通群消息仍交给主会话。会话委派和项目任务均只向调用方返回结果与本地文件路径，由主 Agent 或调用程序处理交付。`--project` 不注入主会话的文件交付规则，也不上传附件、设置权限或执行输出中的交付标记；新建任务和续跑旧会话都遵循此规则。

项目任务的 `run` / `follow-up` 可用 `--request-id` 防止超时重试重复执行：同一归属、同一编号及相同输入返回原任务，输入不同则拒绝，daemon 重启后仍有效。重启不会自动重跑未完成任务；遗留非终态任务标为失败，已有原生会话可显式续跑。

HTTP 使用原 `/agents/…` 路径并增加 `?project=<项目名>`，Bearer 凭据来自 daemon 启动时生成的私有 `agent-project-client.json`（状态目录内，本机同用户读取，重启后轮换）。CLI 自动读取，无需配置或输出凭据。项目凭据只用于显式项目路由，会话和 worker 凭据不能用来调用项目路由。请求体可增加 `request_id`；`requester_open_id`（CLI `--requester`）保留为调用方记录，不触发文件交付或授权。响应中的 `binding: "project"`、`project` 标明归属。旧会话接口保持原调用方式。

## 飞书任务清单

发 `task`，点“启用”可为当前项目创建并绑定 `<project>[lodestar]` 任务清单。主群、同一项目的所有 WT 及其 BTW/FK 临时群共用清单。在其中任一群删除清单，都作用于整个项目；删除需要在卡片上再次确认，会删除整个清单及其中任务。该面板管理清单绑定，任务执行由用户和 Agent 安排。

## 本机通知

脚本可通过 HTTP 向项目群发送通知，支持 `info`、`warn`、`error`，以及本地图片、交互按钮或文字回复：

```bash
curl -sS -X POST http://127.0.0.1:9876/notify \
  -H 'Content-Type: application/json' \
  -d '{"project":"ops","level":"error","text":"构建失败，截图如下","images":["/abs/shot.png"]}'
```

按钮点击结果可以 POST 到指定的本机 `callback`，或通过 `GET /notify/result/<notify_id>` 查询。需要文字回复时设置 `allow_reply: true`，卡片会提供“回复”按钮；文字回复模式与自定义按钮模式不能同时启用。字段和协议见 [feishu-notify Skill](../src/notify-skill.ts)。daemon 启动时会将该 Skill 同步到 Codex 和 Claude 的 Skill 目录。

通知 JSON 正文上限为 4 MiB，超出返回 `413`；图片仍通过本地路径提供。按钮回调或文字回复发送期间若 daemon 中断，重启后会显示“送达状态未知”并禁止再次发送，请先向接收方核实处理结果。通知状态文件无法读取或 JSON 损坏会明确阻止启动，避免丢失去重记录后重复执行。

## 文件与生图

Agent 用 `[[send: /abs/path]]` 交付本地文件。**默认沿用直接发送聊天附件的方式**，单文件不能超过 30 MB（30 × 1024 × 1024 字节）；超限需先压缩或分卷。原来的文件、图片消息通道保留。

Lodestar 启动 Agent 时按本群设置直接注入文件交付约定：云空间模式只说明交付标记；聊天附件模式在标记旁附上大小上限和交付前检查要求。文件交付由宿主处理，无需安装或调用 Skill，Agent 无需查询接口或配置来判断交付方式。Agent 只生成、检查本地文件并输出交付标记，不读取飞书凭据，不操作上传、分片、权限或卡片接口；这些由 Lodestar 统一完成。交付标记是提交请求，实际结果以附件、交付卡及错误提示为准。

安装或更新时会自动删除旧 `lodestar-files` Skill 在 Codex、Claude 和共享插件目录中的受管副本；新版 daemon 启动时也会清理。清理沿用本机数据目录设置，失败会明确报错；显式设置 `LODESTAR_DISABLE_SKILL_SYNC=1` 时保留手工管理的 Skill。

在需要的群中发送 `files on`，开启当前工作目录的云空间交付。同一目录下的主群、BTW/FK 临时群及目录别名共享此开关；WT 使用自己的独立设置，默认聊天附件。在任一同目录群执行 `files off` 会一起切回附件。每个群的云空间文件夹和权限仍各自独立，继承云空间模式的临时群在首次交付时创建自己的文件夹。每个群按 `chat_id` 绑定一个固定文件夹，文件夹名与实际群名一致；之后该群各轮交付都直接放入这个文件夹，不再按轮次创建目录。重启后继续复用原目录，同名群之间独立。群改名后，下次云空间交付或再次执行 `files on` 会同步文件夹名称；目录丢失或不可访问时明确报错，不自动新建空目录掩盖问题。

云空间模式下，每轮结束后发送独立“交付文件”卡片，**只列本轮新交付文件**的名称、大小和访问链接。点击文件名打开文件；点击“管理群文件”打开飞书原生文件夹，查看该群所有历史云空间交付文件，并使用重命名、移动和删除等功能。开启者和后续交付发起人会获得群文件夹管理权限，群成员可查看。文件不自动清理；历史卡片是交付时的记录，文件夹展示当前状态，已删除文件的旧链接会失效。

`files` 显示当前工作目录、交付模式和本群文件夹入口，`files off` 将同目录各群恢复为聊天附件。目录开关与群文件夹绑定分开保存在私有 `file-delivery-groups.json`，关闭不会删除云空间文件，重新开启继续复用原目录。每轮在输入交给 Agent 时固定交付方式，避免文件生成后规则改变。切换开关在同目录各会话的下一轮用户任务生效，已有进程会收到一次完整的交付约定更新，无需重启；普通输入不重复附加规则，后台续跑沿用进程已收到的约定。之前发送到聊天的附件不删除，也不自动迁移至云空间。旧版按群保存的开关会按已知工作目录迁移，已有文件夹继续保留；同目录旧开关冲突时明确报错，发送 `files on` 或 `files off` 统一即可。

**云空间需要同时开通应用身份权限 `drive:drive`、`drive:file:upload`**；后者是文件夹自动改名接口单独要求的权限，前者不能替代。安装向导的[完整权限清单](feishu-permissions.json)已包含这两项，升级用户可补齐后发布飞书应用版本。权限开通不自动开启云空间功能。整个过程不依赖飞书 CLI，也不需要用户授权登录。云空间交付须有可识别的发起人，缺少身份或权限时明确报错。不超过 20 MB 的文件整文件上传，更大的文件按飞书策略分片；实际大小上限与容量由账号决定，不能把企业基础版的认证限额直接套用于飞书个人版。云空间失败不会自动切回聊天附件。自动生图仍沿用下面的图片展示规则。

新上传文件会单独关闭“组织内或互联网获得链接即可访问”的分享入口，并读回确认后才发布交付链接；文件夹关闭链接分享不会自动覆盖新文件的默认设置。群成员通过群文件夹的协作者权限访问。已有协作者仍可按飞书权限设置进行人工分享，本功能不阻止人工转授权。

聊天消息、卡片写入和聊天附件/图片上传遇到短暂故障时，会在一分钟恢复窗口内自动重试；窗口内恢复成功不在群里告警，仍失败才提示，并保留具体诊断。卡片的重试、写入确认与流式重开共用同一个窗口，服务端要求更长等待时不会提前重发。每次实际操作有自己的恢复窗口，排队与上传后发送等多个步骤的耗时可能累加。本地文件问题和主动取消立即处理。云空间创建目录、上传完成等操作仍保持有限重试，避免扩大重复创建风险；分片重试复用相同内容，上传期间本地大文件发生修改会中止完成上传。停止或重启会话会取消未完成的云空间上传，已上传文件保留；链接查询、权限或交付卡发送失败也会明确显示。

Codex 生图完成后，提示词和图片放在同一个折叠面板中，点击展开查看图片并放大预览。无法嵌入时，图片仍会单独发送。
